# Упражнения E506 для Live Coding

Каталог содержит шесть самостоятельных упражнений на C++ для интервью клиента E506. Каждое упражнение рассчитано на requirements-first flow с GoogleTest и GoogleMock, а не на алгоритмическую головоломку.

## Как работать с упражнениями

1. Открыть только README выбранного упражнения.
2. Запустить таймер на шестьдесят минут.
3. Первые пять минут вслух задавать перечисленные уточняющие вопросы.
4. Записать идентификаторы требований и получить воображаемое согласование интервьюера.
5. Определить интерфейсы и mocks до реализации.
6. Написать позитивные, граничные, негативные тесты и тесты отказов.
7. Реализовать только согласованное поведение.
8. В конце сопоставить требования с тестами и назвать отсутствующие integration- и target-evidence.
9. Сравнить ход рассуждений с двуязычными файлами Reasoning упражнения и подробной методикой в родительском документе LiveCoding.

## Структура кода

Каждое упражнение содержит:

- `include/` — публичный контракт и интерфейсы зависимостей;
- `tests/` — исполняемую спецификацию на GoogleTest и GoogleMock;
- `solution/` — полную эталонную реализацию;
- `CMakeLists.txt` — самостоятельную сборку, которая по умолчанию использует эталонное решение и позволяет передать путь к собственной реализации через переменную конкретной задачи.

В репозитории нет намеренно незавершённой реализации. Для тренировки нужно создать отдельную папку `work` внутри выбранного упражнения, реализовать в ней объявленный контракт и передать путь к исходному файлу через CMake-переменную, указанную в README упражнения. Так эталонное решение остаётся неизменным, а цикл тестирования от красного к зелёному воспроизводится одинаково.

## Сборка всех эталонных решений

Необходимы CMake 3.20 или новее и компилятор C++17. Включённый `vcpkg.json` объявляет зависимость от GoogleTest. Можно использовать toolchain vcpkg либо предоставить уже установленный пакет GoogleTest, экспортирующий `GTest::gmock_main`.

```text
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

Команды выполняются из `E506/LiveCoding`. Каждое упражнение также можно отдельно сконфигурировать и собрать из его собственной папки.

При использовании vcpkg из PowerShell команда конфигурации выглядит так:

```text
cmake -S . -B build -DCMAKE_TOOLCHAIN_FILE="$env:VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake"
```

## Стандарт кодирования и границы проверки

Упражнения используют C++17; в них рассмотрены отдельные вопросы, связанные с MISRA C++:2023. В коде компонентов проверка возраста timestamps теперь исключает знаковое переполнение, а steering limiter отклоняет интервал, который невозможно представить в типе времени. Switch выбора цвета ambient light явно обрабатывает неподдерживаемое значение. В учебных онлайн-снимках однострочные тела условных операторов заключены в блоки. Эти изменения улучшают конкретные свойства и не являются заявлением о полном соответствии MISRA.

Для заявления о соответствии нужны применимый набор правил, настройки проекта, надёжные средства проверки и документированные отклонения. Лицензионный текст правил MISRA, настроенный MISRA-анализатор и подтверждения для компилятора и библиотек целевой системы в рамках упражнения недоступны. Google Test, Google Mock и тестовые части учебных снимков — инфраструктура для host-side обучения, а не проверенные production-компоненты. Интерфейсы, использование стандартной библиотеки, исключения, предположения об источнике времени и остальные применимые правила требуют отдельного review по правилам конкретного проекта. MISRA Compliance:2020: https://www.misra.org.uk/app/uploads/2021/06/MISRA-Compliance-2020.pdf

## Правило scope

Значения ASIL являются частью учебного обсуждения, а не заявлением об опыте кандидата. Реальный ASIL выводится из HARA на уровне item и распределённых safety requirements. В упражнении могут быть заданы предположения, но нельзя классифицировать класс C++ только по его названию.
