CABIN AMBIENT-LIGHT CONTROLLER — ХОД РАССУЖДЕНИЙ

1. ОПРЕДЕЛИТЬ ЗАДАЧУ

Пересказываю задание: восстановить предпочитаемый цвет при запуске и обрабатывать изменения пользователя, сохраняя согласованность оборудования, состояния в памяти и хранилища. Уточняю допустимые цвета, отсутствие или ошибку сохранённого значения, порядок apply и save, частичный отказ и повторные запросы. Driver и storage — внешние зависимости.

2. СОГЛАСОВАТЬ ПОВЕДЕНИЕ ПРИ ОТКАЗАХ

Поддерживаются WarmWhite, White, Blue и Red; цвет по умолчанию — WarmWhite. При запуске применяется корректное сохранённое значение. Если значения нет или оно неподдерживаемое, выбирается default и сохраняется только после успешного применения; ошибочное значение диагностируется. Неподдерживаемый запрос во время работы завершается ошибкой без вызовов driver и storage. Для нового корректного цвета сначала применяется оборудование. При отказе сохраняется активное состояние, save не вызывается и сообщается DriverFailure. Если после успешного apply не прошёл save, новый цвет остаётся активным, сообщается PersistenceFailure, а операция возвращает false: это частичный успех, а не откат.

3. РАЗОБРАТЬ СОСТОЯНИЕ И ПОРЯДОК

Активный цвет — optional: до успешного применения он может быть неизвестен. После успеха apply обновляю активное состояние до save, поскольку свет уже изменился. Запрос активного цвета возвращает true без вызовов driver и storage. Поэтому повтор того же цвета после ошибки сохранения по этому контракту не повторяет save и не очищает диагностику; другое успешное изменение может её очистить. Обсуждаю этот компромисс и не обещаю автоматический retry.

Корректный сохранённый цвет применяется без повторной записи. Неподдерживаемое сохранённое значение диагностируется, затем default применяется и сохраняется. Временные ошибки driver и persistence отслеживаются, чтобы исключить повторные сообщения и очистить их после соответствующего успеха. UnsupportedValue сообщается напрямую, без хранения как дедуплицируемого временного состояния.

4. РАЗРАБАТЫВАТЬ И ТЕСТИРОВАТЬ

Внедряю ILightDriver, IPreferenceStore и IDiagnosticSink. Начинаю с корректного сохранённого цвета, затем проверяю отсутствие значения и порядок apply до save. Добавляю неподдерживаемые сохранённое и runtime значения: после cast или десериализации enum всё ещё может содержать неподдерживаемое значение. Проверяю отказ driver без изменения состояния и без save, а также отказ save с изменённым цветом и результатом false. Проверяю отсутствие действий при повторе цвета, диагностику и последующее другое успешное изменение. Для порядка использую InSequence; проверяю состояние и вызовы, а не только результат. Связываю REQ-LGT-001–010 с тестами и запускаю существующий набор.

5. ЗАВЕРШИТЬ ВЕРИФИКАЦИЕЙ

Integration проверяет формат хранения и интерфейс driver, target tests — запуск и работу лампы, product tests — восприятие цвета и сохранение после выключения питания. QM — предварительное рассуждение для описанной функции комфорта; если этот свет передаёт предупреждения безопасности, необходимо пересмотреть item и анализ опасностей.
