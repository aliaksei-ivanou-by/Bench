ЗАПУСК WHEEL SPEED MONITOR В ОНЛАЙН-КОМПИЛЯТОРЕ

1. ЧТО ПОНАДОБИТСЯ

В упражнении используются C++17, Google Test и Google Mock. Просто вставить файл тестов в пустой онлайн-компилятор недостаточно: ему нужны заголовок компонента, реализация и подключённые библиотеки. Для удобства рядом лежит OnlineCompiler.cpp: в нём объединены текущие WheelSpeedMonitor.h, эталонный WheelSpeedMonitor.cpp, WheelSpeedMonitorTest.cpp и функция main для запуска тестов.

На 29 октября 2026 года этот файл проверен через Compiler Explorer с x86-64 GCC 13.2, опцией -std=c++17 и библиотекой Google Test версии trunk: запустились и прошли 13 тестов. Версия trunk меняется со временем; доступность библиотек и расположение элементов интерфейса сайта также могут измениться.

2. ЗАПУСК В COMPILER EXPLORER

1. Откройте https://godbolt.org/ и выберите язык C++.
2. В IDE откройте файл OnlineCompiler.cpp из этой папки, скопируйте его целиком и замените содержимое редактора на сайте.
3. Добавьте панель выполнения через Add new... → Executor или Compiler Execution Only. Если панель уже открыта, используйте её. Обычная панель компилятора с ассемблерным кодом сама по себе ещё не означает, что тесты запущены.
4. В панели выполнения выберите x86-64 GCC 13.2 и в поле Compiler options укажите -std=c++17.
5. В той же панели откройте Libraries, найдите Google Test и выберите версию trunk. Она включает заголовки и библиотеки Google Test и Google Mock. Дождитесь настройки библиотеки. Если отдельная панель компилятора тоже открыта, настройка её библиотек не обязательно распространяется на панель выполнения.
6. Нажмите кнопку компиляции или выполнения в панели Executor, если автоматический запуск отключён. Дождитесь Compiler output и вывода программы. Код тестов не требует ввода в stdin.
7. Проверьте, что в выводе программы есть строка [  PASSED  ] 13 tests. Четыре из них — отдельные запуски одного параметризованного теста. Нулевой код выхода означает успех; если есть [  FAILED  ], изучите сообщение теста.

3. КАК ТРЕНИРОВАТЬСЯ

Для прохождения с пустого проекта откройте OnlineSteps/Guide_RU.md: там 25 файлов с последовательным добавлением тестов и логики. Каждый этап можно целиком вставить в Executor.

В OnlineCompiler.cpp сначала расположен контракт, затем реализация, затем тесты и main. Для тренировки изменяйте в редакторе сайта только реализацию WheelSpeedMonitor и повторно запускайте тесты. Например, временно замените порог 1.5 на 1.0: тест точной границы сам по себе может не показать эту ошибку за один цикл, поэтому проверьте, какие именно проверки действительно краснеют, и обсудите недостающее покрытие. После эксперимента восстановите исходное значение.

Файл OnlineCompiler.cpp — самостоятельная копия, а не автоматически обновляемое представление трёх исходных файлов. Если менять исходный код упражнения или тесты, копию нужно обновить отдельно. Для обычной локальной разработки используйте исходные файлы и CMake, описанные в README упражнения; OnlineCompiler.cpp не добавлен в CMake-сборку.

4. ЕСЛИ НЕ РАБОТАЕТ

- gmock/gmock.h или gtest/gtest.h: No such file or directory — проверьте, что Google Test версии trunk выбрана именно в панели выполнения и что язык выбран C++.
- cannot find -lgtest или -lgmock, undefined reference — проверьте, что выбрана библиотека Google Test и используется Linux x86-64 GCC 13.2. На проверенной конфигурации trunk линковался успешно; версия 1.10.0 при проверке не нашла -lgtestd и -lgmockd.
- undefined reference to main — убедитесь, что скопирован весь OnlineCompiler.cpp, включая функцию main в конце. Не добавляйте вторую функцию main.
- Ошибки optional или вложенного namespace — проверьте опцию -std=c++17.
- Нет строк [ RUN ] и [ PASSED ] — проверьте именно вывод программы в Executor: успешная компиляция не равна выполнению тестов.
- Если вывод отличается, проверьте выбранную версию библиотеки, GCC и содержимое файла; сайт мог обновиться после даты проверки.

OnlineGDB поддерживает несколько исходных файлов, но наличие нужных Google Test и Google Mock в его окружении для этого упражнения не проверено. Поэтому здесь приведён проверенный путь через Compiler Explorer.

Источники: https://godbolt.org/ и https://godbolt.org/api/libraries/c++ — интерфейс и каталог библиотек Compiler Explorer; проверка 29 октября 2026 года.
