2. ТЕКСТ ДЛЯ ИНТЕРВЬЮ

Здравствуйте, меня зовут Aliaksei Ivanou. Я software engineer с более чем четырнадцатилетним опытом в инженерии и исследованиях и разработке. Мой основной фокус — разработка на C и C++, а в последней работе я сочетал C++17, Qt и embedded Linux с Yocto. Ранее я разрабатывал алгоритмы обработки изображений в MATLAB.

Я расскажу об опыте по доменам, а затем подробнее остановлюсь на последнем embedded-проекте.

Первый домен — телекоммуникации и embedded-устройства. С мая 2022 года я работаю в роли Software Engineer на SIP-Based Phone Software — платформе настольных телефонов для аудио- и видеосвязи. Моя работа охватывает приложение на C++ и Qt, кастомизированный Linphone SDK, провижининг устройств и интеграцию с системой Linux на базе Yocto для оборудования NXP i.MX. После обзора доменов я вернусь к этой платформе подробнее.

Второй домен — библиотечные системы и долгоживущий бэкенд. С мая 2019 по апрель 2022 года я работал в роли Software Engineer на Library System. Я был одним из трёх C-разработчиков, совместно отвечавших за существующий бэкенд C89. Я реализовывал функциональность, исправления и рефакторинг на C, эпизодически меняя Java или Scala. Я прослеживал сбои по логам сервисов и использовал gdb, core dumps и Valgrind под Linux. Сервисы данных работали с PostgreSQL и MySQL.

Третий домен — промышленные измерения. С марта по май 2019 года я работал в роли Software Engineer на 3D Reconstruction Software for Industrial Applications. Я разработал прототип на C++, который объединял профили нескольких двумерных лазерных сканеров в облако точек. Для реконструкции я использовал Point Cloud Library, а для сравнения и визуализации — Open3D, проверяя промежуточные этапы на записанных данных.

Четвёртый домен — спутниковая съёмка и изображения для БПЛА. С августа 2017 по декабрь 2018 года я работал в роли Software Engineer на Software Modules for UAV, разрабатывая в MATLAB алгоритмы дебайеризации, преобразования форматов, стабилизации и слияния изображений. Я проверял алгоритмы на представительных изображениях и участвовал в испытательных полётах БПЛА как оператор оптической полезной нагрузки.

С марта 2016 по март 2017 года я работал в роли Software Engineer на Remote Sensing Satellites Database. Я разработал справочную базу на Ruby on Rails и PostgreSQL для поиска параметров спутников и миссий.

С августа 2012 по март 2016 года я работал в роли Software Engineer на Software for Processing and Analysis of Satellite Earth Observation Images. Моя работа в MATLAB включала сшивку кадров, радиометрическое согласование, прогноз типа изображения, автоматическую оценку разрешения и алгоритм сжатия семейства ADPCM. Для бортового сжатия я проектировал и проверял алгоритм с учётом небольшого вычислительного бюджета; команда flight software реализовывала его на целевой платформе.

Теперь подробнее расскажу о проекте SIP-телефона: он ближе всего к этой роли.

Продукт поддерживает аудиотелефоны и модели с камерой. Его программная часть включает приложение Qt, кастомизированный SIP SDK, инструменты провижининга и образ embedded Linux. Видимое пользователю состояние зависит от сгенерированной конфигурации, настроек устройства, SDK и моделей приложения. Я работал на стыке этих частей преимущественно как C++ и Qt разработчик.

Например, я реализовал watchdog регистрации и переключение на резервный сервер и обратно в кастомизированном SDK liblinphone, а затем интегрировал его API в приложение и провижининг. Сначала я попробовал переключать серверы на уровне Qt, но перенёс машину состояний в SDK, поскольку жизненный цикл регистрации принадлежал именно ему. На физических устройствах я проверял потерю и восстановление сервера, аутентификацию и отображаемое состояние. Я также рефакторил обработку звонков, разделяя сессии, сервисы, адаптеры и представление; более широкий рефакторинг был завершён как внутренняя архитектурная работа.

На стороне Linux продукт уже использовал Yocto и BitBake. Я работал в унаследованных слоях и адаптировал рецепты и упаковку для приложения Qt, SDK и медиазависимостей, состава образов для разных моделей, скриптов и runtime-сервисов. Полный образ объединял приложение и его зависимости для целевого устройства NXP i.MX. Мой вклад — интеграция внутри существующей платформы, в том числе на границе с BSP, а не владение всем BSP или создание дистрибутива с нуля.

Хороший пример — запуск устройства. Приложение зависело от готовности графического окружения, установленных файлов, сервисов и оборудования. То, что выглядело как ошибка Qt, могло оказаться отсутствующим файлом, неверным порядком запуска сервиса или недоступным сокетом Wayland. Я исследовал образ с помощью логов, gdb и gdbserver и проверял результат на физических телефонах. Компонентные тесты помогали с изолированной логикой, но полный запуск, аудио, видео и поведение оборудования требовали проверки на целевом устройстве.

Я также мигрировал инструмент провижининга WinForms с .NET Framework 4.8 на .NET 8 и разрабатывал сценарии конфигурации и обнаружения устройств с SNMP, DHCP и TFTP. Сгенерированные настройки должны были соответствовать тем, что телефон действительно применял.

Во всех этих доменах мой общий подход — понять полный путь данных или управления, внести точечное изменение в существующую систему и проверить его на нужной границе. Для этой роли я могу предложить практическую разработку на C++, интеграцию образов Yocto и диагностику embedded Linux, а также опыт работы между приложением, SDK, сервисами и физическим оборудованием.
